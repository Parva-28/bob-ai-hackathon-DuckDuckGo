How the pipeline actually works

YieldGuard is an agent that calls fourteen MCP tools over real models and real data. Nothing below is a mock: every box is a tool that runs, and every number is measured on a held-out set. The one thing the diagrams make explicit is which numbers are calibrated and which are only ranked — that distinction is the point of the system, not a footnote.

1 · The tool chain

Bob calls each tool separately, then passes the four evidence results into rank_root_causes as arguments. The agent does not invent evidence — it routes it. A hypothesis that cites no tool output is rejected at the MCP boundary. Section 2 is how that sequencing is decided — the server itself has no notion of an investigation.

Why the fan-in matters. The four evidence tools never talk to each other. If the CNN says Center and telemetry shows no drift on the centre-affecting tools, the ranking has to reconcile that itself — and it shows the conflict rather than smoothing it.

2 · Who actually drives the chain — IBM Bob

The server has no idea what an investigation is. It exposes fourteen independent tools and answers one call at a time. Bob is the thing that decides which tool to call, in what order, and what to carry forward. Take Bob out and there is no pipeline — only a toolbox.

What the skill actually encodes

Ordering get_lot_data always first when a lot is named — it returns the wafer_map_ref and sensor_signature every later tool needs. “Never invent an image path or a sensor dict.”
Branching Post-mortem vs pre-run. On a lot that has not run, steps 1 and 2 do not apply — there is no wafer and no sensor data, so the agent must not call them and then report 0.0 as if it were a clean result.
Carrying rank_root_causes takes the results of tools 1–4 as arguments. The agent does the fusing; the server cannot, because it never saw the earlier calls.
Honesty “Never claim more confidence than rank_root_causes returned.” · “An empty input is a data gap, not a finding.” · “Do not flatten a distributed ranking into one answer.” · “Confidence values are relative rankings, not calibrated probabilities.”
Self-report pipeline_status exists so that when a judge asks “what here is real?”, the agent reports which tools are backed by trained models rather than guessing.
The rules are enforced twice, on purpose. A prompt rule is a request — an LLM can ignore it. So the same constraint also lives in the server: a hypothesis with no cited evidence is stripped by the MCP boundary before Bob ever sees it, and a warning is returned in its place. The skill tells the agent to be honest; the server makes dishonesty structurally unavailable. Neither layer is trusted alone.

And it is measured. The orchestration is scored end-to-end on 18 fixtures — correct tool sequence, evidence actually cited, no confidence inflation, gaps reported as gaps. Live, with real model calls, the current result is 16/18 (range 13–16 over five runs). The two remaining failures are in the report, not hidden: see section 6.

Why validation comes first. A softmax always returns a class. Fed an empty array, the classifier reported Scratch at confidence 1.00 — a confident answer about nothing. Confidence cannot guard against out-of-distribution input, so a separate gate has to. 8 of 8 adversarial inputs refused; both real samples accepted.

4 · Two confidence regimes, deliberately not mixed

This is the part most yield-analysis demos blur. We keep the two apart and label every response with which one produced it.

Constructed lotsPHM 2016 CMP
Data SECOM sensors + WM-811K maps, joined by us CONSTRUCTED Traces and outcome from the same wafer MEASURED
Confidence llm_uncalibrated — an ordinal ranking under policy ceilings A conformal interval with 94.0% measured coverage
Can it refuse? No. It always returns a ranking. Yes — the RI/GSI gate returns no interval at all
Valid claim “Check these three first.” “Removal rate lands in [a, b] 90% of the time.”
Invalid claim “88% confident it was ETCH-07.” “Coverage holds in every band.” (it is 84.0% in p75–90)
The result that makes the case. Same model, same runs. The point estimate caught 34.7% of excursions. The conformal interval caught 93.9%. Abstaining on 42.1% of runs separated MAE 5.06 (abstained) from 2.88 (retained) — a 1.76× gap, which is what makes the abstention worth acting on.

5 · What keeps it honest

Validation first Garbage in gets refused, not classified. No confident answers about nothing.
No precedent is a finding Zero-similarity cases are dropped rather than served as “the nearest match.” An empty result is the correct answer.
Evidence citation enforced A hypothesis with no evidence summary is rejected by the MCP server, not by the prompt.
Provenance on every response Stamped measured or constructed, with the invalid claims listed explicitly alongside the valid ones.
Cognitive forcing The UI will not fetch the ranking until the engineer records their own read first. Explanations raise acceptance whether or not they are correct (Bansal et al., CHI 2021); only forcing functions reduce over-reliance (Buçinca et al., 2021).
Own sensors reported Deviating sensors are ranked over the caller’s own inputs, not over the imputed 582-feature vector — ranking the latter returns imputation artifacts.

Two things we did not get to work, stated plainly.
GSI shows no signal (ROC-AUC 0.450). It measures covariate shift — novel inputs. The failure between CMP stages A and B is concept drift: the same inputs map to a different output. GSI is the wrong instrument for it, and we report that rather than quietly dropping the metric.

The reasoning layer has no abstention gate. It always produces a ranking, and its confidence is ordinal, not a probability — hence the llm_uncalibrated stamp and the policy ceilings. The CMP branch is where abstention was actually solved. Extending it to the reasoning layer is the next step, not something already shipped.
