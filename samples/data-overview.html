Read the sensor values against each other

The failing lot peaks at 1.93σ. The passing lot peaks at 2.02σ — the passing lot deviates more. That is not an error in the sample; it is what SECOM is, and it is why the anomaly detector reaches ROC-AUC 0.583 and fail-class recall 0.286 regardless of tuning.

The loudest failing row in SECOM peaks at 21.8σ. Using it would make the detector look decisive. Choosing the medoid instead is the difference between demonstrating a system and flattering one.

It is also why Track A moved to the PHM 2016 CMP dataset, where the process measurements and the outcome are recorded on the same wafer — the one place in this system where a sensor-to-outcome claim is measured rather than asserted. See the Prediction & abstention screen.

Try it live

Upload runs the real chain on data the system has never seen. No fixture is consulted; the response reports data_provenance.kind = "uploaded".

curl -X POST http://127.0.0.1:8787/api/analyze-upload \
  -F "wafer_map=@samples/wafer_defect.npy" \
  -F 'sensors={"sensor_571":-1.93,"sensor_480":1.84}' \
  -F "equipment_ids=ETCH-07"
